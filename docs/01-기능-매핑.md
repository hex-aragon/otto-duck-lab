# Open Duck Mini v2 기능 → 오또봇 + 누코드

Open Duck Mini v2(이하 ODM)가 하는 일을 하나씩 보고, 관절 4개짜리 오또봇에서 무엇을 어떻게 옮길지 정리했다.
ODM 쪽 사실은 [next/open-duck-mini/README.md](next/open-duck-mini/README.md)(2026-11-02 저장소 확인)를 근거로 했다.

판정: ✅ 1단계에서 함 · 🟡 선택(시간 남으면) · ❌ 오또봇에서는 안 함

## 한눈에 보기

| # | ODM 기능 | ODM 구현 | 오또봇 + NU40 구현 | 판정 | 다음 단계로 가져가는 것 |
|---|---|---|---|---|---|
| 1 | 두 발 걷기 | RL 정책(ONNX) 50Hz, 관절 14개 | 사인파 오실레이터 50Hz, 관절 4개 (`gait.h`) | ✅ | 제어 주기, 관절 목표 = 기본 자세 + 출력이라는 구조 |
| 2 | 게임패드 조종 | Xbox 패드 블루투스 → 파이 | 웹 블루투스 컨트롤러, 키보드 누르고 있기 (`web/index.html`) | ✅ | 명령 끊김 시 정지(타임아웃) 설계 |
| 3 | 자세 측정 | BNO055 (9축, 자체 융합) | 6축 IMU + 상보 필터 (`imu.h`) | ✅ | 축 방향 맞추기, 자세 추정 원리 |
| 4 | 넘어짐 대응 | 정책 입력에 IMU가 들어감 | 넘어짐 · 들림 감지 → 즉시 서보 힘 빼기 (`posture.h`) | ✅ | 안전 정지 로직 (ODM은 별도 안전 처리 없음 → 직접 추가할 부분) |
| 5 | 관절 영점 | `duck_config.json`, `find_soft_offsets.py` | 웹 트림 슬라이더 → 보드 플래시 저장 | ✅ | 영점 개념, 설정을 코드와 분리 |
| 6 | 데이터 기록 | `record_data.py`, `plot_recorded_data.py` | BLE 텔레메트리 · 특징값 스트림 → 웹 CSV | ✅ | sim2real 비교에 필요한 기록 습관 |
| 7 | 학습된 모델을 로봇에서 실행 | 파이에서 ONNX 추론 | **NU40에서 TinyML 추론** (자세 분류) | ✅ | 학습 → 내보내기 → 탑재 → 검증 파이프라인 |
| 8 | 발 접촉 센서 | 발 스위치 2개 (GPIO) | 발바닥 마이크로스위치 2개 | 🟡 | 정책 입력으로 쓰이는 접촉 신호 이해 |
| 9 | 머리 움직임 (목 · 머리 4관절) | STS3215 4개 | 오또 휴머노이드처럼 서보 1~2개 추가 (같은 PWM 모듈 남는 채널 없음 → 두 번째 모듈) | 🟡 | 표현 동작 |
| 10 | 눈 LED · 안테나 서보 | GPIO · PWM | 8×8 LED 매트릭스 또는 보드 LED로 감정 표시 | 🟡 | |
| 11 | 소리 | MAX98357A I2S 앰프 | 부저 `tone()` (HwPWM2 사용 — 서보와 모듈 분리됨) | 🟡 | |
| 12 | 기준 걸음 생성 | `reference_motion_generator` → 다항식 | 오실레이터 파라미터(A · O · φ · T) 탐색 | 🟡 | "걸음을 숫자 몇 개로 표현한다"는 개념 |
| 13 | 시뮬레이션 학습 | MuJoCo Playground, 엔비디아 GPU 필요 | 오또 MuJoCo 모델로 파라미터 탐색 (CPU 가능) | 🟡 | MuJoCo 모델(MJCF) 만들기, 도메인 랜덤화 감 잡기 |
| 14 | 카메라 · 프로젝터 | 파이 카메라 | 해당 없음 (NU40에 카메라 처리 여력 없음) | ❌ | |
| 15 | RL 걷기 정책 실물 실행 | 14관절 정책 | 관절 4개 오또는 사인파가 더 낫다 | ❌ | 2단계에서 공개 정책으로 직접 |

## 누코드만 할 수 있는 것 (ODM에 없는 것)

| 기능 | 설명 |
|---|---|
| 에어밴드 스틱 = 조종기 | 기존 스틱(NU40 + IMU)의 타격 class를 웹이 받아 오또 동작으로 바꾼다. 스틱 펌웨어는 그대로. 스네어 → 앞으로, 하이햇 → 왼쪽, 탐 → 오른쪽, 크래시 → 춤, 지휘 박 → 위아래 |
| 음악 오또 | 지휘 모드 박에 맞춰 춤. Microduck 계획의 "음악 오리"와 같은 목표를 먼저 작은 로봇으로 해 본다 |
| 저전력 BLE 5 | 파이보다 훨씬 적은 전력. 대신 계산 여력이 작아 모델은 KB 단위여야 한다 |

## 일부러 안 하는 것

- **오또에 RL 정책 올리기**: 관절 4개 로봇은 사인파로 충분히 걷고, RL 학습 환경을 처음부터 만드는 비용이 크다. RL은 2단계에서 ODM 공개 정책과 Playground로 배운다.
- **오또봇 원본 코드 복사**: OttoDIYLib은 GPL-3.0이다. 저장소 라이선스를 정하기 전까지 동작 파라미터만 참고하고 코드는 새로 썼다.
