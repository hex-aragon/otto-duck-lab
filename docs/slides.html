PART 1

로봇 기초 개념

수식 없이, 그림으로

개념 1

로봇은 계속 돈다

걷기는 "각도를 한 번 보내고 끝"이 아니다. 흔들리는 동안 계속 재고 계속 고친다. 고장 찾을 때도 ①②③을 따로 확인한다.
개념 2

서보 모터와 "영점"

  • 서보는 "이 각도로 가"라는 명령을 받는다
  • 영점 = 각도의 기준점. 조립하면 조금씩 틀어진다
  • 틀어진 만큼 숫자로 보정 = 트림
  • 왼쪽 · 오른쪽 순서가 바뀌거나 방향이 반대면 → 아무리 좋은 AI도 못 걷는다
오또봇: 웹 화면 트림 슬라이더로 차렷 자세를 반듯하게 → 보드에 저장
개념 3

전원과 통신은 다른 선이다

🔋

전원 = 힘

전압(V): 부품이 정한 범위에 맞춘다

전류(A): 모터가 힘쓸 때 확 늘어난다

📨

통신 = 명령

"어느 모터를 몇 도로"를 전달

USB가 연결됐다고 모터 힘까지 준비된 건 아니다

⚠️ 서보 전원을 보드에서 끌어오지 않는다. 배터리 → 서보로 따로 주고 GND(−)만 묶는다.
전원이 약하면 재부팅 · 힘 빠짐 · 통신 오류처럼 보인다 → 통신 문제도 전원부터 의심.
개념 4

IMU: 몸이 얼마나 기울었나

↔️
Roll

좌우 기울기

↕️
Pitch

앞뒤 숙임

🔄
Yaw

방향 전환

손으로 로봇을 앞으로 숙였을 때 화면의 pitch가 +로 가는지 확인. 반대면 코드의 축 설정을 바꾼다.

센서 두 개를 섞는다 (상보 필터)

장점단점
자이로 (회전 속도)빠르다오차가 쌓인다
가속도 (중력 방향)오차가 안 쌓인다흔들림에 약하다

→ 자이로 98% + 가속도 2%를 매번 섞으면 둘의 장점만 남는다

개념 5

오또봇은 "파도"로 걷는다

서보마다 크기(A) · 중심(O) · 타이밍(φ) · 주기(T) 네 숫자만 정하면 동작이 된다.

걷기 · 돌기 · 문워크 · 흔들기 = 숫자 조합만 다름. 오리 로봇의 "기준 걸음 생성기"도 같은 생각을 더 복잡하게 한 것.

개념 6

오리 로봇은 "AI 정책"으로 걷는다

지금 상태기울기 · 관절 위치 · 속도
+
사람 명령"앞으로", "고개 돌려"
→
정책 (AI 모델).onnx 파일
→
관절 14개 목표1초에 50번
  • 정책은 가상 세계(시뮬레이터)에서 수백만 번 넘어지며 배운다 = 강화학습
  • 파일만 있다고 끝이 아님: 관절 순서 · 입력 형식 · 영점이 학습 때와 같아야 한다
  • 다른 로봇용 정책은 확장자(.onnx)가 같아도 못 쓴다
개념 7

먼저 "있는 모델 돌리기", 학습은 나중

✅ 기존 정책 실행

설치 · 입력 · 모터 · 센서를 맞추는 일

문제는 대부분 설정과 실물의 차이

먼저

⏳ 새 정책 학습

관측 · 행동 · 보상을 설계 → 시뮬레이터에서 학습

GPU · 비용 · 검증 시간이 크다

나중

강화학습 3요소 — 관측(로봇이 보는 것) · 행동(할 수 있는 움직임) · 보상(잘했나 점수). PPO는 이걸로 정책을 고치는 알고리즘 이름.
개념 8

가상에선 걷는데 실물은 왜 넘어지나 (sim2real)

가상과 다른 점실물에서 보이는 것먼저 볼 것
영점 · 센서 방향한쪽으로 계속 기운다차렷 자세, IMU 축
모터 힘 · 속도 · 기어 유격발을 못 든다, 떤다정확한 모터 모델, 나사
전원 · 통신 지연힘쓸 때 불안정, 반응이 늦다전압, 제어 주기 기록
한 번에 하나만 바꾸고, 바꾸기 전후를 같은 시험으로 비교한다.
도메인 랜덤화 = 가상에서 마찰 · 무게 · 지연을 일부러 흔들어 학습 → 실물에 강해진다.

오리 로봇 원본 코드엔 이런 안전 정지가 없다 → 여기서 만든 걸 2단계에 그대로 가져간다.

TinyML

왜 AI가 필요한가: "들어 올림"

규칙(if문)으로 되는 것

  • 앞으로 넘어짐 → 중력이 앞쪽
  • 옆으로 넘어짐 → 중력이 옆쪽

규칙으로 어려운 것

  • 손에 들고 흔듦 vs 걷는 중 흔들림
  • 사람마다 다르게 듦

TinyML = 보드 안의 아주 작은 AI

입력: 최근 1초 센서 값 요약 8개

모델: 8 → 12 → 6 신경망

크기: 약 0.7KB (사진 한 장의 1/1000)

출력: 서 있음 · 걷는 중 · 앞/뒤/옆 넘어짐 · 들림

TinyML

데이터 모으기부터 보드에 올리기까지

① 라벨 고르기"들어 올림"
→
② 기록로봇을 그 상태로
→
③ 학습브라우저에서 1초
→
④ 내보내기posture_model.h
→
⑤ 업로드보드가 AI로 판단
라벨마다 30개 이상, 2명 이상이 따로 모은다. 한 사람 데이터만 쓰면 정확도가 부풀려진다.
목표: 검증 정확도 90% 이상, 넘어졌는데 "서 있음"이라고 하는 실수는 0에 가깝게
