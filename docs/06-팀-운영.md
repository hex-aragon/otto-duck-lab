# 팀 운영 · 제작 지원 가이드

> 2026-11-04 팀 설명 슬라이드의 운영 · 일정 판단 · 제작 지원 부분을 문서로 옮겼다. 원래 Open Duck Mini 4주 제작용이었지만 **오또봇 1단계에도 그대로 쓴다.** 시설 조건은 11/4에 공식 안내를 읽은 내용이고 바뀌었을 수 있다 — 예약 · 신청 전에 반드시 다시 확인한다.

## 1. 개발 여력 계산

- 실제 개발은 **리더 한 명분**이다. 4주 × 주 40시간 = 160시간을 가정하고, 그중 **약 30%는 고장 · 배송 · 재작업**에 남긴다 → 새로 만드는 일은 약 110시간 안에서 범위를 정한다.
- 서포트 팀원의 시간은 리더 개발 시간에 더하지 않는다. 대신 **리더가 전화하고 자료 찾는 시간을 줄이는 데** 쓴다.
- 주 5일 집중, 주말은 휴식과 최소 점검. 4주는 달력 기간이고 실제 집중 작업은 평일 약 20일이다.

## 2. 결과물을 단계로 나누기

| 단계 | 보여줄 결과 | 판단 |
|---|---|---|
| A · 실물 기본 시연 | 센서 · 모터 확인, 지지대 위 자세 · 인사 | 우선 목표 |
| B · 실물 보행 | 짧은 저속 이동 · 정지 반복 | A 이후 도전 목표 |
| C · 가상 시연 | 가상 로봇 이동 · 정지 · 표현 동작 + 설명 영상 | 실물이 늦어질 때 대체안 |

보행 문제 하나 때문에 모든 성과를 잃지 않도록 나눈다. **A와 C는 B의 성공을 증명하지 않는다.** 껍데기만 출력한 모형은 작동하는 시제품과 다르다. 최종 결과에는 실물 · 가상 여부와 지지대 사용 여부를 적는다.

## 3. 일정을 지키는 판단 시점

| 시점 | 확인할 사실 | 어려우면 |
|---|---|---|
| D3 | 모터 · 출력 · 보드의 정확한 도착일 | 대여 · 확보된 키트로 바꾸거나 목표 재협의 |
| D7 | 2주차 조립에 필요한 부품과 공간 | 실물 범위 축소 또는 가상 시연 전환 |
| D14 | 기본 자세 · 센서 · 관절 동작 | 보행 확대 중단, 기본 동작 안정화 |
| D21 | 전체 시연 1회 완주 | **기능 동결**, 반복 검증에 집중 |

D21 이후에 새 학습 · 새 입력 장치 · 모터 교체를 넣으면 검증 시간이 사라진다. 지원 선정이나 회신을 기다리는 동안에도 예제 실행과 기록은 계속한다.

## 4. 4주차 검증 기준 (제안값)

| 시험 | 완료 기준 |
|---|---|
| 정해진 60초 시연 | 같은 절차 10회 중 9회 이상 |
| 정지 동작 | 10회 모두. 한 번이라도 실패하면 원인 수정 후 재시험 |
| 입력 연결 끊김 | 정해 둔 정지 상태로 가는지, 걸린 시간 기록 |
| 재시작 · 설명서 | 서포트 팀원이 설명서만 보고 실행, 관찰 결과 기록 |

10회 중 9회는 팀 합의용 제안값이며 안전 인증이나 장기 신뢰성을 뜻하지 않는다. 성공 영상 한 번보다 **같은 절차를 반복한 기록**이 설득력 있다. 실패 이유, 넘어졌는지, 입력 지연도 함께 적는다.

## 5. 역할은 직업명이 아니라 맡을 결과물로

| 맡을 일 | 리더에게 넘길 결과 |
|---|---|
| 리더: 사양 · 설치 · 조립 · 개발 · 통합 | 작동 버전과 기술 판단 |
| 시설 조사, 신청서 초안, 설명 · 발표 | 출처 · 조건 · 일정 · 비용 비교표 |
| 로그와 실험 정리 (Python 경험이 있으면) | 시도별 설정 · 결과표, 가능하면 기록 자동화 |
| 사진 · 영상 · 부품 재고 · 시험 체크 | 재고표와 시연별 체크리스트 |

직업명만으로 로봇 개발 경험을 가정하지 않는다. **첫날 30분으로 각자 가능한 시간과 맡을 일을 확인한다.** 실제 능력과 시간을 확인하기 전에는 독립적인 제어 개발을 일정에 넣지 않는다.

### 서포트는 "확인된 사실"을 넘긴다

좋은 인계 예시:
> "A시설은 PLA만 가능하고 TPU는 불가합니다. 다음 주 화요일 출력 가능하다는 회신을 받았습니다. 견적과 원문을 첨부했습니다."

후보 링크만 많이 넘기면 리더가 다시 읽고 비교해야 한다. **확인된 내용 / 모르는 내용 / 다음 질문**으로 나눠 넘긴다. 시설 연락은 담당자 한 명이 맡아 중복 문의를 줄인다.

### 매일 운영

- 오전 10분: 오늘 목표와 막힌 일
- 리더: 2~3시간 집중 작업 묶음
- 저녁 15분: 실행 결과와 다음 할 일
- 결정과 근거는 메신저가 아니라 **GitHub 이슈 · 보드**에 모은다 (할 일 · 담당 · 완료 기준 · 기한 · 근거 링크 · 확인 상태)

### 가천 무료 출력 (11/4 공고 기준)

- 2026-11-30까지, 조기 종료 가능. 흰색 PLA 무료. 동일 모델 최대 2개, 신청자당 최대 2회, 1건 최대 24시간, STL과 G-code 제출
- 취미 · 개인 소장 목적 제한이 있다 → **실제 목적을 사실대로 설명**하고 대상인지 묻는다. 창업 목적을 꾸미지 않는다
- 오리 로봇 51개 전체를 맡길 수 있다고 계산하지 않는다. TPU는 별도 경로. **팀원 명의를 나눠 수량 제한을 우회하지 않는다**
- 오또봇은 출력물이 6개 정도라 이 지원에 더 잘 맞는다 `TODO: 1단계 출력 담당이 확인`

## 7. 출력 · 구매 준비

## 8. 예산 관리

| 묶음 | 확인할 것 | 기준 |
|---|---|---|
| 핵심 부품 | 모터 · 보드 · 센서 · 전원 · 기계 부품 | 모델 · 수량 · 현재 국내 납기 |
| 제작 | 출력, 재출력, 후가공 | 지원 적용 전후 견적을 나눠 적기 |
| 작업 환경 | 공구 · 작업대 · 교통 · 장비 교육 | 무료 공간도 이동 비용 포함 |
| 예비비 | 고장 · 누락 · 추가 배송 | 확정 견적 합계의 20% 제안 |

총액 상한은 D1에 정한다. 오래된 유럽 부품표 금액을 국내 도착 총액으로 쓰지 않는다. 구매표에는 단가 · 수량 · 배송비 · 세금 포함 여부 · 도착 예정일 · 판매 링크를 남긴다. 지원금 · 무료 출력이 확정되기 전에는 지출 예정액에서 빼지 않는다.
