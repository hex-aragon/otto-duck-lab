## 1. 큰 그림

```
[내 PC 또는 클라우드]                              [로봇]
 시뮬레이션에서 수천 마리 훈련                      50Hz 제어 반복
 (mjlab, MuJoCo Warp, PPO)                         센서값 61개 읽기
        │ 훈련 결과 내보내기                              │
        ▼                                                ▼
   policy.onnx ── Hugging Face 저장소 ── 설치 ──▶ 정책 실행 → 모터 목표 14개
```

1초에 50번 "센서값을 넣으면 모터 목표가 나오는 작은 인공 신경망"을 돌리는 것이 동작의 핵심이다. 이 신경망을 **정책(policy)** 이라고 부른다.

## 3. 공부 순서

1. **첫날:** 온라인 시뮬레이터에서 오리를 조종해 본다. 소개 글을 읽는다.
2. **1~2주:** Hugging Face 강화학습 강좌에서 기초와 PPO 부분을 본다.
3. **동시에:** MuJoCo 문서에서 모델 파일과 관절 부분만 읽는다.
4. **2~3주:** `microduck_rl`의 걷기 학습을 그대로 돌린 뒤, 보상 값을 하나씩 바꿔 본다.
5. **논문:** 디즈니 BDX 논문을 읽는다. 이 로봇 계열의 설계 사고방식을 알 수 있다.
6. **실물 전:** BAM과 다이나믹셀 문서를 본다.
7. **필요할 때만:** 러스트, Yocto, 전자 설계.

## 4. 로봇 사양

### 제품

| 항목 | 내용 | 출처 |
|---|---|---|
| 크기 · 무게 | 높이 25cm, 폭 14cm, 800g 미만 | 보도 자료 |
| 컴퓨터 | RK3566, RAM 1GB, 저장 32GB | 보도 자료 |
| 인공지능 칩 | 0.8 TOPS NPU. 작은 물체 찾기 정도만 가능, 큰 모델은 외부에서 실행 | CNX Software, 공식 FAQ |
| 센서 | 전면 카메라, 8×8 거리 센서, IMU 2개(몸통 · 머리), 마이크 | 보도 자료 |
| 출력 | 스피커, 얼굴 LED, 부리 집게 | 보도 자료, 설계 문서 |
| 통신 | Wi-Fi, 블루투스, NFC 안테나 2개 | 보도 자료 |
| 배터리 | 탈착식 NP-F550, 2600mAh, 약 1시간 | 보도 자료 |

카메라 해상도, 무선 규격, 라이다 범위는 보도 자료에도 "잠정"으로 적혀 있다.

### 모터 · 내부 버스 (공식 설계 문서 `robotd-design.md`)

| 항목 | 내용 |
|---|---|
| 버스 | UART 1개(`/dev/ttyS2`), 1Mbps, 다이나믹셀 v2 |
| 왼쪽 다리 | ID 20~24 |
| 오른쪽 다리 | ID 10~14 |
| 목 · 머리 · 입 | ID 30~34 |
| 몸통 IMU 보드 | ID 200 (`imu_to_dxl` v2), 모터와 같은 선 사용 |
| 모터 펌웨어 | v46 이상 필요 (빠른 묶음 읽기 때문) |
| 전압 | 2S 팩 그대로, 6.6V(빈 상태)~8.2V(완충) |

관절 이름과 움직임 범위는 `robot_walk.xml`에 있다. 왼쪽 · 오른쪽 다리: `hip_yaw`, `hip_roll`, `hip_pitch`, `knee`, `ankle`. 머리: `neck_pitch`, `head_pitch`, `head_yaw`, `head_roll`. 합쳐서 14개이며, 입 모터를 더하면 15개다.

### 정책의 입력과 출력

```
입력 61개 = 자이로(3) + 중력 방향(3) + 관절 위치(14) + 관절 속도(14)
          + 직전 출력(14) + 명령(13)
명령 13개 = 이동 속도(3) + 머리(4) + 몸(6)
출력 14개 → 모터 목표 = 기본 자세 + 배율 × 출력
```

모든 공식 정책이 같은 형식이라 실행 중에 바꿀 수 있다. 형식이 다르면 로봇이 거부한다.

## 5. 소프트웨어 구조

프로그램(데몬) 여러 개가 로봇에서 돌아가고, 로컬 소켓과 JSON-RPC로 대화한다. 앱, 콘솔, 게임패드, 내 스크립트가 같은 명령을 쓴다.

| 프로그램 | 하는 일 |
|---|---|
| `robotd` | 모터, 센서, 정책, 안전. 50Hz 반복 |
| `configd` | Wi-Fi, 이름, PIN, 게임패드 연결 정보 |
| `updaterd` | 서명된 업데이트 설치, 문제 시 되돌리기 |
| `mediad` | 카메라 · 소리, WebRTC 전송 |
| `btd` | 블루투스 설정 경로 |
| `padd`, `netpadd` | 게임패드, 네트워크 게임패드 입력 |
| `tofd` | 거리 센서 |
| `robotctl`, `duckctl` | 로봇 위 명령 도구, 노트북에서 블루투스로 쓰는 명령 도구 |

## 6. 학습 환경에서 알아 둘 것

- **프레임워크:** mjlab (MuJoCo Warp + rsl_rl), 알고리즘 PPO
- **걷기 학습 시간:** 4096개 환경으로 쓸 만한 걸음까지 약 1~2시간 (엔비디아 그래픽카드 기준, 공식 README)
- **공식 학습 과제:** 걷기, 넘어짐 복구, 일어서기, 앉기, 바닥 집기, 공차기, 앞구르기, 롤러스케이트 계열
- **가장 중요한 부분:** 공식 README는 이 크기에서는 모터 모델의 정확도가 현실과의 차이 대부분이라고 설명한다
- **배포 주의:** 체크포인트를 직접 변환하지 말고 반드시 `export.py`가 만든 ONNX를 쓴다. 입력 정규화 값이 그 안에 들어 있다

## 7. 안전

- 정책이 낸 목표는 모터 범위로만 제한되고, 관절별 범위 제한은 설계 문서 기준으로 아직 없다. 내가 만든 정책은 처음에 손으로 받칠 준비를 하고 시험한다.
- 넘어짐 판정은 알리기만 할 뿐 정책을 막지 않는다.
- 게임패드 UDP에는 인증이 없다. 집 안의 믿을 수 있는 네트워크에서만 켠다. 같은 네트워크의 누구나 조종하고 전원까지 끌 수 있다.
- 배터리는 리튬 이온이다. 복제할 경우 합선, 충전, 전압 관리는 내 책임이다.
