# 소프트웨어 구조

## 1. 전체 그림

```
                 [브라우저 web/index.html]
                  ├ 조종 (버튼 · 키보드)
                  ├ 트림 슬라이더
                  └ TinyML: 특징값 기록 → 학습 → posture_model.h 내보내기
                           │ BLE (Nordic UART)
                           ▼
[오또봇 NU40 firmware/otto_nu40]
  100Hz IMU → 기울기(상보 필터)
   25Hz 특징 창(1초) → 5Hz 자세 분류(규칙 또는 TinyML) → 넘어짐/들림이면 서보 힘 빼기
   50Hz 동작 중이면 사인파 → 서보 목표 각도 → 하드웨어 PWM
   10Hz 텔레메트리
```

**왜 브라우저로 조종하나:** 앱을 설치하지 않고 폰(안드로이드)이나 PC 크롬에서 바로 연결된다. 텔레메트리 · 데이터 수집 · 학습까지 한 화면에서 할 수 있다.

## 2. 펌웨어 (`firmware/otto_nu40/`)

| 파일 | 역할 | 아두이노 의존 |
|---|---|---|
| `otto_nu40.ino` | BLE, 명령 처리, 상태 머신, 서보 PWM, 트림 저장 | 있음 |
| `gait.h` | 동작 → 사인파 파라미터, 시각 → 서보 각도 | 없음 (PC에서 시험 가능) |
| `imu.h` | IMU 자동 감지, 읽기, 축 맞추기, 기울기 | Wire |
| `posture.h` | 특징 8개 계산, 규칙/신경망 분류 | 없음 |

### 상태 머신

```
          동작 명령               동작 끝 · 정지 · 명령 1초 끊김 · BLE 끊김
  대기 ───────────────▶ 동작 중 ─────────────────────────────▶ 대기
   ▲                       │
   │                       │ 넘어짐/들림 2회 연속(≈400ms)
   │                       ▼
   └── 다음 동작 명령 ── 힘 뺌 ◀── 다시 섬 ── 넘어짐 · 들림 (서보 펄스 끊음, 명령 거부)
```

### 서보 구동

아두이노 `Servo` 라이브러리 대신 **nRF52 하드웨어 PWM을 직접** 쓴다 (1MHz, 20ms 주기, 1µs 단위).
PC에 일반 Servo 라이브러리가 깔려 있으면 BSP 것 대신 그게 잡혀 컴파일이 깨지는 문제가 실제로 있었다 (2026-11-11 확인).
펄스 0 = 힘 빠짐. 각도 → 펄스: `SERVO_MIN_US(500) + (SERVO_MAX_US(2400) − 500) × 각도/180`.

### 동작 목록 (`gait.h`)

| id | 이름 | 한 글자 명령 |
|---|---|---|
| 0 | 차렷 | `h` |
| 1 | 앞으로 | `w` |
| 2 | 뒤로 | `s` |
| 3 | 왼쪽 돌기 | `a` |
| 4 | 오른쪽 돌기 | `d` |
| 5 | 위아래 | `1` |
| 6 | 흔들기 | `2` |
| 7 | 문워크 왼쪽 | `3` |
| 8 | 문워크 오른쪽 | (웹 · ACTION 명령만) |
| 9 | 까치발 | `4` |

그 밖의 한 글자 명령: `x` 정지 · `r` 힘 빼기 · `t` 트림 출력. 시리얼 모니터와 BLE 둘 다 받는다.

## 3. BLE 프로토콜

Nordic UART Service (nRF52 표준 시리얼 서비스). 광고 이름 `Otto-NU`.
- Service `6e400001-b5a3-f393-e0a9-e50e24dcca9e`
- RX(write, 브라우저 → 보드) `6e400002-…` · TX(notify, 보드 → 브라우저) `6e400003-…`

모든 값은 little-endian. 한 번의 write = 명령 하나 (20바이트 이하).

### 명령 (브라우저 → 보드)

| 0번 바이트 | 이름 | 나머지 | 설명 |
|---|---|---|---|
| `0x01` | ACTION | `[1]` 동작 id · `[2]` 걸음 수(0 = 계속) · `[3]` 주기 ÷ 10ms (0 = 1000ms) | 0 = 계속이면 1초 안에 같은 명령이나 PING이 다시 와야 유지 |
| `0x02` | STOP | | 차렷으로 |
| `0x03` | TRIM | `[1]` 서보 0~3 · `[2]` int8 도 (±30) | 차렷 자세에서 바로 반영 |
| `0x04` | SAVE | | 트림을 플래시에 저장 |
| `0x05` | STREAM | `[1]` bit0 텔레메트리 · bit1 특징값 · bit2 원시 IMU | 기본 bit0만 |
| `0x06` | RELAX | | 서보 힘 빼기 |
| `0x07` | PING | | 명령 끊김 타이머만 리셋 |
| `0x20` 이상 1바이트 | 한 글자 | | 위 한 글자 명령 |

### 보고 (보드 → 브라우저)

| 0번 바이트 | 이름 | 길이 | 내용 |
|---|---|---|---|
| `0x90` | 텔레메트리 | 12 | `[1]` 상태 · `[2]` 동작 · `[3]` 자세 class · `[4-5]` pitch×100 · `[6-7]` roll×100 · `[8-9]` 가속도 크기 mg · `[10]` 신뢰도 ×255 · `[11]` bit0 IMU, bit1 TinyML, bit2 서보 힘 |
| `0x92` | 특징값 | 17 | `[1..16]` int16 × 8, 값 × 1000 (`posture.h` 순서) |
| `0x93` | 원시 IMU | 13 | 가속도 mg × 3, 자이로 °/s×10 × 3 (25Hz) |
| `0x94` | 이벤트 | 3 | `[1]` 1 넘어짐 · 2 들림 · 3 다시 섬 · 4 동작 끝 · 5 명령 끊김 |
| `0x95` | 트림 | 5 | `[1..4]` int8 |

**상태 값:** 0 대기 · 1 동작 중 · 2 넘어짐 · 3 들림 · 4 힘 뺌
**자세 class:** 0 서 있음 · 1 걷는 중 · 2 앞으로 넘어짐 · 3 뒤로 넘어짐 · 4 옆으로 넘어짐 · 5 들어 올림

## 4. 웹 (`web/index.html`)

빌드 도구 없는 파일 하나. 팀원 누구나 열어서 바로 쓴다.

| 영역 | 기능 |
|---|---|
| 연결 | 오또봇(`Otto`로 시작하는 이름) 연결 |
| 조종 | 방향 패드 · W A S D 누르고 있기(300ms마다 재전송) · 춤 버튼 · 걸음 주기 |
| 상태 | 텔레메트리 표시 |
| 트림 | 서보별 ±30° 슬라이더, 보드 저장 |
| TinyML | 라벨 선택 → 기록 → 라벨별 개수 → 학습(검증 정확도 · 혼동 행렬) → `posture_model.h` 내보내기 · CSV 저장/불러오기 |

GATT 쓰기는 동시에 두 번 하면 오류가 나므로 Promise 줄 세우기로 순서대로 보낸다.

| 항목 | 결과 |
